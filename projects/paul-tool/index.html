PAUL_Tool 生活排程工具

每日任務與強制就寢：Windows 服務守著時間，關掉介面也躲不掉

概述

以 Go 撰寫的 Windows 服務負責排程與電源控制，Electron + React 桌面程式負責任務清單與提醒。就寢時間會逐步提前，時間到就全螢幕提醒並休眠或關機。從 WPF 雛形出發，先改寫成 Wails（Go + React），最後換成 Electron 搭配 Go 服務。

重點功能

  • 今日任務清單：期限、完成狀態與逾期標示
  • 漸進式就寢：預設每 2 天提前 30 分鐘，從 05:30 逐步移向 01:00
  • 提醒階梯：就寢前 2 小時到 1 分鐘逐級提醒，最後逐秒倒數
  • 全螢幕就寢畫面：30 秒後預設休眠，也可以選擇關機
  • named pipe 權限控管：只允許本機的互動使用者讀寫，遠端連線一律拒絕

我負責的部分

  • 從自己晚睡的問題出發定義需求：就寢時間要逐步提前、時間到要真的休眠，而且不能輕易繞過。
  • 決定架構邊界：只有 Windows 服務能控制電源與排程，桌面程式不需要管理員權限。
  • 驗收並追查事故：曾發生錯過就寢時間 14 小時後才突然休眠，我要求先用真實的資料庫重現，再修正並加上回歸測試。

挑戰與做法

使用者只要關掉程式就能逃過就寢。
排程與電源控制放在開機自動啟動的 Windows 服務，異常結束會自動重啟；桌面程式不在時，服務會在使用者的工作階段重新開啟它，等不到就直接執行並記錄。
休眠指令執行到一半當機，重開後可能再休眠一次。
每次就寢都記錄「準備、已執行、成功」三個階段，成功後先寫入資料庫再做其他事，並用系統層級的 mutex 確保同時只有一個行程能控制電源。
錯過的就寢時間不該在之後突然補執行。
只有稽核紀錄證明服務曾在當時發出警告、而且延遲不到 1 小時，才會補執行；這條規則是在真實事故後加上的，並附回歸測試。

現在回頭看

  • 從 WPF 到 Wails 再到 Electron 換了三次技術，學到換框架前要先列出真正的痛點；最後換掉 Wails 的理由是安裝程式、自動更新和熱重載，而且 151 個 React 測試原封不動通過。
  • 電源控制要能在測試裡注入假的執行器，否則測試本身就可能把電腦關掉。
  • 系統管理員仍然可以停止服務，這個限制直接寫在 README 裡，沒有假裝做到完全無法繞過。
