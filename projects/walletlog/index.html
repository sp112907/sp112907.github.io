WalletLog 記帳系統

每日收支、分期付款、帳戶與帳單，一個人的家庭財務後台

概述

React + Ant Design 前端，Go + Gin + GORM 後端，資料存在 MariaDB，用 Docker Compose 部署並由 nginx 反向代理。以 Google 帳號登入，後端自行簽發存取權杖與可輪替的刷新權杖。

重點功能

  • 每日收支與標籤，月報、分類統計、趨勢與年度報表
  • 分期付款自動計入每個月份，並同步扣減信用卡可用額度
  • 資產分組：帳戶、多張信用卡共用額度、外幣與帳戶間轉帳
  • 帳單：每人一組、應付與實付、一鍵複製上月，可以唯讀分享給家人
  • 預算分配與提醒

我負責的部分

  • 從自己的記帳需求出發，定義分期付款、帳單分攤與資產分組的規則。
  • 決定登入與權杖策略：只用 Google 登入，刷新權杖放在前端腳本讀不到的 Cookie，每次刷新都輪替。
  • 設定 AI 協作的驗收關卡：每輪結束前必須通過 go build 與 go test。

挑戰與做法

分期付款如果拆成每月一筆付款紀錄，修改期數就要同步改很多筆資料。
分期只存一筆，用「年 × 12 + 月」比較月份，在每個月的報表中動態計入；剩餘期數由日期推算，前後端用同一套公式。
帳戶餘額如果另外存一個欄位，很容易和明細對不起來。
餘額不落地：期初餘額加收入減支出，用一次分組查詢算出。
兩個轉帳請求同時送出，可能把餘額扣成負數。
在交易中用帶條件的單一更新扣款，餘額不足就直接失敗。

現在回頭看

  • 金額在 Go 端用 float64，雖然資料庫欄位是 decimal；今天會改用整數分或 decimal 型別。
  • 測試太少：後端只有 7 個登入相關的測試，前端沒有測試，而且還有型別與 lint 錯誤沒清。
  • 趨勢與年度報表每個月各跑 3 次查詢，資料一多就該改成一次分組查詢。
