2020手寫

遊戲啟動器與多執行緒更新

2012 年沒寫完的更新器，2020 年重寫成多執行緒分段下載的啟動器

概述

為自架的遊戲伺服器寫的 Windows 啟動器：開啟時比對伺服器上的版本清單，依序下載並解壓更新檔，最後啟動遊戲。2012 年第一次嘗試只做到列出新版本；2020 年用 C# 重寫，完成多執行緒下載、7z 解壓與伺服器狀態偵測。

重點功能

  • 比對伺服器上的 XML 版本清單，只下載比本機新的更新
  • 依檔案大小開 1–10 條執行緒，以 HTTP Range 分段下載再依序合併
  • 下載後用 7z 解壓，依系統位元自動選擇 32 或 64 位元的函式庫
  • 每套用完一個更新就寫入版本號，中斷後從最後完成的更新繼續
  • TCP 探測加逾時判斷伺服器狀態，伺服器掛掉時也不會卡住

我負責的部分

  • 需求、介面與更新流程都由我一個人完成。
  • 設計伺服器端的 XML 版本清單格式，以及以日期為基礎的版本號（例如 20200415000）。

挑戰與做法

更新檔很大時，單一連線下載太慢。
依檔案大小決定執行緒數，每條執行緒用 HTTP Range 下載一段，最後依順序合併，並把 .NET 預設的連線上限調高。
下載到一半斷線，重開後不想從頭來。
更新依版本順序逐一套用，每完成一個就寫回本機版本號，下次只下載剩下的。
伺服器掛掉時，啟動器不該整個卡住。
用非同步 TCP 連線加逾時檢查伺服器的連接埠，並在介面上顯示伺服器狀態燈。

現在回頭看

  • 沒有任何檔案校驗；今天會替每個更新檔加上 SHA-256 雜湊，並改用 HTTPS。
  • 多條執行緒同時寫入同一個 List 沒有加鎖，例外也被吞掉；今天會用 async/await 和明確的錯誤處理。
  • 2012 年的雛形停在下載函式沒有接上、開始按鈕也沒有啟動遊戲，八年後才真正把它做完。
